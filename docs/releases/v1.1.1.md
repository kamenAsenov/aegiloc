# Aegiloc v1.1.1

Released: 2026-08-24

v1.1.1 is a product-history and safety-communication patch. It adds no healing capability and does
not change scoring, confidence, margin, context, revalidation, or execution behavior.

## Project lineage

Healwright v1.0.1 was the initial GitHub evaluation release. Aegiloc is its renamed successor with a
new repository, package import, CLI binary, environment prefix, and default evidence path. It is not
a drop-in package or CLI rename.

No package was published under the former name, so there are no npm consumers or registry artifacts
to migrate. Existing version-1 target registry data remains compatible. Source-checkout evaluators
should follow the [v1.1 migration guide](../MIGRATION-v1.1.md).

## Action-risk guidance

- Treat new `uncheck` targets as `proposal-only`, particularly for consent, terms, permissions,
  subscriptions, and destructive controls.
- Start `hover` in `observe` or `proposal-only`, because a wrong hover can reveal a different menu or
  change the context for a later action.
- Permit automatic execution only for an exact target reviewed as reversible and low impact.
- Technical support for an action is not blanket authorization to heal it.

This is maintainer guidance, not a silent parser-default change. Older registries retain their
documented compatibility behavior and should declare `executionRisk` explicitly when reviewed.

## Honest analytics boundary

Target-health rates, drift age, score/margin ranges, and recent outcomes are history-derived
indicators computed from retained test evidence supplied to Aegiloc. They are not production
telemetry, a service-level measure, or proof of reliability in client systems or unobserved runs.

## Distribution

This release remains a GitHub source release. No npm package is published. Package, SBOM, and
provenance artifacts remain review outputs rather than registry-publication authorization.

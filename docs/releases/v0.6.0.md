# Healwright v0.6.0 Technical Preview

Status: prepared in source for review; **not tagged, not published to npm, and not a GitHub Release**.

Healwright v0.6.0 packages the conservative runtime into a coherent local evaluation experience.
It adds onboarding commands, a static evidence viewer, and a deterministic realistic demo without
broadening what the framework is allowed to heal.

## Highlights

- `healwright --help`, `init`, `validate`, `doctor`, and `view` through a compiled package `bin`;
- safe, non-overwriting starter registry creation and strict runtime validation;
- a self-contained, escaped, no-JavaScript report generated only from matching canonical evidence;
- a realistic storefront demo with ordinary Playwright, one clear safe heal, and one ambiguous
  rejection;
- updated technical-preview, CLI, viewer, demo, risk, and non-use documentation;
- strict CLI, report, XSS, overwrite, mismatch, package, and Chromium demo tests.

## Safety behavior

The release does not add assertion healing, source rewriting, automatic proposal application, visual
AI, or remote services. The static viewer is read-only evidence. `init` and `view` refuse silent
overwrite. The ambiguous demo succeeds only by proving that no candidate was executed.

## Try the source preview

```bash
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm build
node dist/cli.js doctor
pnpm example:realistic
open test-results/realistic-demo/viewer/index.html
```

The repository remains the installation source until a separate reviewed npm publication decision.

## Compatibility

- Node.js 20 or newer;
- pnpm 11 for repository workflows;
- Playwright Test `>=1.50.0 <2` as a peer dependency;
- Chromium is the only qualified browser;
- existing runtime APIs, registry version 1, and evidence schema version 1 remain intact.

## Not yet production-ready

This is a pre-1.0 technical preview. It lacks demonstrated production adoption, cross-browser
qualification, authenticated evidence origin, long-running performance data, and a stable v1 API.
Teams should use it for local evaluation and portfolio review, not assume operational readiness.

## Release integrity

Creating this document or setting `package.json` to `0.6.0` does not publish a release. A maintainer
must separately review and merge the branch, confirm green CI, approve a tag, optionally create a
GitHub Release, and make an independent npm publication decision.

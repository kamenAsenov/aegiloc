# Healwright v0.4.0

Healwright is an experimental, deterministic self-healing layer for Playwright Test. It recovers
only from proven locator drift, keeps scoring inspectable, and treats a false-positive heal as worse
than a failed heal.

v0.4.0 adds explicit execution risk and post-run governance to the existing guarded runtime,
canonical evidence, and human-reviewed proposal workflow.

## Highlights

- `automatic` and `proposal-only` risk is declared per semantic target.
- Protected targets can produce diagnostic candidate evidence but cannot execute a replacement.
- Run, target, and target/action budgets limit successful or rejected recovery attempts.
- Successful and rejected baselines detect growth relative to reviewed expectations.
- Temporary waivers require exact scope, a reason, and a valid UTC expiration.
- Waivers affect budget counts only; they cannot influence runtime safety.
- Retry-aware JSON and Markdown health summaries are deterministic and schema validated.
- The provider-neutral governance CLI uses distinct exit codes for pass, policy failure, and malformed
  input.
- CI verifies canonical evidence, evaluates policy, and retains the resulting artifacts.

## Safety boundaries

Healwright does not heal assertions, business logic, authentication, test data, API/network errors,
or genuine product regressions. Guarded execution still requires proven absence, action-compatible
candidate collection, mandatory semantic identity, confidence, a safe runner-up margin, immediate
second-pass agreement, unique accessible resolution, audit output, and screenshot capture.

Successful evidence never rewrites source or `registry/targets.json`. Locator proposals remain
`review-required` artifacts for a human-controlled change.

## Try it locally

```bash
git clone https://github.com/kamenAsenov/healwright.git
cd healwright
git checkout v0.4.0
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm build
pnpm test:healing
pnpm governance:evaluate
```

Verify the tagged checkout with:

```bash
pnpm format:check
pnpm lint
pnpm typecheck
pnpm build
pnpm package:check
pnpm test:reporter:parallel
pnpm test
pnpm evidence:verify
pnpm governance:evaluate
pnpm pack --dry-run --json
```

## Known limitations

- Chromium is the only qualified browser in v0.4.0.
- The package is not published to npm.
- Candidate collection focuses on common interactive HTML and ARIA patterns.
- Proposal hashes detect later modification but do not authenticate the original evidence source.
- Proposal-only observations cannot yet generate locator proposals without successful guarded
  execution evidence.
- Reporter aggregation is scoped to one Playwright or merged-report process.

## Why pre-1.0

Cross-browser qualification, performance budgets, stronger optional evidence integrity, supply-chain
artifacts, longer-running reliability checks, and an explicit compatibility review remain on the
roadmap before v1.0. v0.4.0 is a serious evaluation and portfolio checkpoint, not a claim of mature
enterprise adoption.
